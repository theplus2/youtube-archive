## 절대 규칙

1. **자막 없이 내용을 쓰지 않는다.** 제목·설명·썸네일만 보고 요약이나 전문을 만들지 말 것. 자막 확보에 실패하면 아래 "자막 확보 실패 시" 절차로 가고, 사용자에게 사실대로 알린다.
2. **요약(Mode B)의 모든 주장은 `transcript.txt`에 근거한다.** 영상에 없는 내용, 외부 지식으로 보충한 내용을 화자의 말처럼 쓰지 않는다. 보충 설명이 필요하면 "(편집자 주)"로 구분한다.
3. **파일명·`<h1>`은 `[카테고리명] 영상 제목`**, 폴더명은 `N.[카테고리명]`. 이 규칙은 `build_doc.py`가 강제하므로 `content.json`의 `category`에는 번호·대괄호 없이 이름만 쓴다(예: `신학&교회`).
4. **전문 교정은 요약이 아니다.** 교정본은 원문의 모든 문장을 담아야 한다. 고칠 수 있는 것은 오인식·맞춤법·띄어쓰기·문장부호·
   자막 분절로 깨진 문법뿐이고, 내용을 줄이거나 보태거나 순서를 바꾸지 않는다. 확신이 없으면 고치지 말고 `(?)` 또는 `[불명확]`을 붙인다.
5. `1.[신학&교회]` 분류 영상의 채널·화자가 한국 주요 교단이 이단·사이비로 규정한 단체 소속이면(또는 불확실하면) 문서를 만들기 전에 사용자에게 알리고 진행 여부를 확인한다. 진행 시 `content.json`의 `notes`에 경고 문구를 넣는다.

## Workflow

### 0단계: 준비

```bash
pip install -q -r requirements.txt
```

**로컬 PC 실행이 기본이다.** 클라우드 세션에서는 YouTube 봇 차단 때문에 1·2순위가 거의 실패하므로, 클라우드에서 실패하면 로컬 실행을 먼저 권한다.
Windows에서는 `python3` 대신 `python`을 쓴다.

Gemini 경로를 쓰려면 `GEMINI_API_KEY`(또는 `GOOGLE_API_KEY`)가 필요하다. 클라우드 환경 설정(세션 제목 표시줄의 환경 메뉴 → Edit)의
Network secrets 또는 환경 변수에 `GEMINI_API_KEY`로 등록되어 있어야 한다. **키를 채팅으로 받지 않는다.**
키가 없으면 3순위 경로만 건너뛰고 나머지는 그대로 동작한다.

### 1단계: 모드 확정

- **Mode A (전문)**: "전문", "전체 텍스트", "대본" 요청 시 → `"mode": "A"`
- **Mode B (시각화 요약)**: "요약", "표 정리", "분석" 요청 또는 지시 없음(기본) → `"mode": "B"`
- **듀얼**: 둘 다 요청 시 → `"mode": "dual"` (요약 뒤에 전문)

### 2단계: 추출

```bash
python3 scripts/yt_fetch.py "<URL>"
```

`work/<VIDEO_ID>/`에 `meta.json`, `transcript.json`, `transcript.txt`가 생긴다. `transcript.txt`를 **끝까지** 읽는다(긴 영상은 나눠서). 종료 코드 3이면 자막 확보 실패다.

전사 확보 순서 (`--via auto`, 기본):

| 순위 | 경로 | 성격 |
| :--- | :--- | :--- |
| 1 | yt-dlp 자막 | 제작자 자막 또는 유튜브 자동 자막 원문 |
| 2 | youtube-transcript-api | 위와 동일, 다른 접근 방식 |
| 3 | `watch` 스킬 → Gemini | YouTube 차단 우회. **AI가 듣고 받아쓴 것**이라 원문 자막이 아님 |

- 이미 차단이 확인된 세션이면 `--via gemini`로 1·2순위를 건너뛰어 시간을 아낀다.
- 원문 자막만 허용하려면 `--via youtube`.
- Gemini 전사(`transcript.kind == "gemini"`)는 누락·오기·환각이 있을 수 있다. 문서에는 경고가 자동으로 들어가며,
  최종 보고에서도 사용자에게 알린다. `coverage`(전사 범위/영상 길이)가 0.9 미만이면 뒷부분 누락 가능성을 따로 알린다.
- Gemini 경로는 영상 URL을 Google에 보낸다. 공개 영상만 대상으로 하고, 비공개·일부공개 영상이면 사용자에게 먼저 묻는다.

**중복 검사**: Drive `search_files`로 `fullText contains '<VIDEO_ID>'`를 조회한다. 이미 문서가 있으면 새로 만들지 말고 사용자에게 링크를 알려 덮어쓸지 묻는다.

#### 자막 확보 실패 시

클라우드 세션의 IP는 YouTube 봇 차단("Sign in to confirm you're not a bot", HTTP 429/403)에 자주 걸린다. 스크립트가 이미 재시도했으므로:

1. 오류가 `GEMINI_API_KEY 미설정`이면 0단계대로 환경 설정에 키를 등록하도록 안내한다(새 세션부터 적용).
2. 1·2순위만 실패하고 Gemini도 일시 오류면 1~2분 뒤 한 번만 더 실행한다.
3. 그래도 실패하면 사용자에게 알리고, 유튜브 영상 설명란의 "스크립트 표시"에서 복사한 텍스트를 붙여넣어 달라고 요청한다 →
   파일로 저장 후 `python3 scripts/yt_fetch.py "<URL>" --transcript-file <파일>` (타임스탬프 줄 자동 인식)
4. 어떤 경우에도 추측으로 문서를 만들지 않는다.
5. `watch` 스킬의 로컬 엔진(yt-dlp 다운로드 + Whisper)은 같은 YouTube 차단에 걸리므로 이 환경에서는 대안이 되지 않는다.

### 3단계: 분류 및 content.json 작성

`config/categories.json`의 `scope`를 기준으로 14개 중 **하나**를 고른다. 두 곳에 걸치면 영상의 주된 논지를 따르고, 판단 근거를 최종 보고에 한 줄로 적는다.

`work/<VIDEO_ID>/content.json`을 작성한다(스키마는 `scripts/build_doc.py` 상단 주석 참조).

- **Mode B `summary`**
  - `thesis`: 핵심 명제. 합쳐서 5~7줄.
  - `logic_tree`: `level` 0(주제) / 1(➔ 논거) / 2(↳ 세부). 기호는 스크립트가 붙이므로 텍스트에 넣지 않는다.
  - `table`: 핵심 요약표. 2~4열.
  - `points`: 상세 논점. 각 논점에 해당 발언이 시작되는 `start`(초)를 넣으면 딥링크가 붙는다.
- **Mode A `sections`** (3-1단계 교정을 먼저 끝낸 뒤 쓴다): `{"start": 초, "anchor": "그 문단의 첫 말(선택)", "title": "소제목"}`.
  - 본문 텍스트는 여기 쓰지 않는다. 스크립트가 교정본(3-1단계)에서 채운다.
  - 소제목은 주제가 바뀌는 문단에서 시작한다. 같은 타임스탬프에 문단이 여럿이면 `anchor`로 시작 문단을 지정한다
    (`python3 -c` 로 `clean_transcript.load()` 결과를 출력해 문단 시각·첫 말을 확인).
  - 영상 챕터가 지나치게 길거나 짧으면 쓰지 말고 주제 단위(보통 2~4분)로 직접 나눈다. 생략하면 챕터 → 5분 단위로 자동 분할.
  - `notes`: '읽기 전에' 상자에 넣을 안내(출연자 확인 결과 등). 교정·전사 출처 안내는 스크립트가 자동으로 넣는다.
  - `corrections`: `[["자막 원문", "교정"], ...]` 주요 교정 어휘 20~30개. 문서 끝 부록 표가 된다.

### 3-1단계: 전문 교정 (Mode A·dual 필수)

```bash
python3 scripts/clean_transcript.py prep work/<VIDEO_ID>
```

`work/<ID>/clean/`에 `01.raw.txt …`(약 2,200자 단위 청크)가 생긴다.

1. **용어 교정표 먼저.** `transcript.txt` 전체를 읽고 오인식된 인명·지명·용어를 `clean/glossary.md`에 정리한다
   (확신하는 교정 / `(?)`를 붙일 추정 / 손대지 않을 불명확 항목을 구분). 출연자 이름은 자기소개·자막·영상 설명으로 확인되는 것만 쓴다.
2. **청크별 교정본 작성.** 각 `NN.raw.txt`를 읽고 `NN.txt`를 쓴다.
   - 문단마다 맨 앞에 `[HH:MM:SS] ` 태그. 그 문단의 첫 말이 들어 있는 원문 줄의 태그를 그대로 복사한다. 시간 역순 금지.
   - 화자가 바뀌면(원문의 `>>`) 새 문단. 한 사람이 길게 말하면 3~6문장마다 자연스러운 곳에서 문단을 나눈다. `>>`는 지운다.
   - 의미 없는 말더듬·중복 단어만 지울 수 있다. `[웃음]` 같은 표기는 둔다. 화자 이름을 지어 붙이지 않는다.
   - 문단은 반드시 문장이 끝나는 곳에서 나눈다(원문 줄 경계에서 나누지 않는다). 말이 끊기면 `…`로 끝낸다.
     문장 부호 없이 끝난 문단은 화자 혼동이 생기므로 `check`가 경고한다.
   - 청크 경계에서 문장이 잘려도 글을 다른 청크로 옮기지 않는다. 마지막 문단을 문장 중간에서 끝내 두면
     스크립트가 다음 청크의 첫 문단을 이어 붙인다.
   - 타임스탬프 없는 사용자 제공 전사는 모든 태그가 `[00:00:00]`이 된다(줄은 약 400자 단위로 나뉜다).
   - 청크가 8개를 넘으면 서브에이전트 여러 개에 나눠 맡길 수 있다. 이때 모두 같은 `glossary.md`와 위 규칙을 따르게 하고,
     돌아온 결과에서 인명 표기가 갈렸는지 `grep`으로 확인해 통일한다.
3. **검사.**

```bash
python3 scripts/clean_transcript.py check work/<VIDEO_ID>
```

다음 중 하나라도 걸리면 실패한다(요약·생략·창작 의심).
- 원문 글자(한글·숫자·영문) 중 교정본에 그대로 남은 비율이 0.88 미만
- 교정본에 대응하는 곳이 없는 원문 연속 구간이 20자 이상 — 출력된 구간을 원문과 대조해 빠진 문장을 되살린다
- 청크 글자 수가 원문의 0.75~1.30배 밖 (0.97 미만은 경고)
`build_doc.py`도 같은 검사를 하므로 통과하지 못하면 문서가 만들어지지 않는다.
교정 없이 원문을 그대로 실어야 할 때만 `content.json`에 `"cleanup": false`를 쓴다(사용자가 원할 때).

### 4단계: 문서 빌드 및 Drive 저장

```bash
python3 scripts/build_doc.py work/<VIDEO_ID>
```

출력 JSON의 `title`, `folder`, `folder_id`, `root_id`, `file_reference`를 사용한다.

1. **폴더 ID 확보**
   - `folder_id`가 있으면 그대로 쓴다.
   - `null`이면 `search_files(query="parentId = '<root_id>' and title contains '<카테고리명>'")`로 찾는다.
   - 그래도 없으면 `create_file(title="<folder>", contentMimeType="application/vnd.google-apps.folder", parentId="<root_id>")`로 만든다.
   - 찾거나 만든 ID는 `config/categories.json`에 기록하고 커밋한다.
2. **문서 생성** — Google Drive 커넥터 `create_file`:
   - `title`: 출력의 `title` 그대로
   - `contentMimeType`: `text/html` (Drive가 Google Docs로 자동 변환)
   - `parentId`: 카테고리 폴더 ID — **생성 시점에 지정하므로 별도 이동이 필요 없다**
   - 본문: `base64Content`에 출력의 `file_reference` 문자열을 그대로 넣는다(파일 내용을 직접 타이핑하지 않음). 경로 구분자는 `/`로 바꿔 넣는다.
     해시 불일치로 거부되면 `sha256sum work/<ID>/doc.html`로 다시 계산해 넣는다. 그래도 안 되면 `doc.html`을 읽어 `textContent`로 전달한다.
3. **검증** — 응답의 `mimeType`이 `application/vnd.google-apps.document`이고 `parentId`가 카테고리 폴더인지 확인한다. 아니면 `update_file(fileId, parentId)`로 바로잡는다.

### 5단계: 보고

사용자에게 문서 링크, 분류와 근거, 모드, 자막 출처(제작자 등록/자동 생성/사용자 제공/Gemini 받아쓰기)를 알린다.
전문이면 교정 결과(주요 교정 몇 가지, `(?)`·`[불명확]`으로 남긴 곳의 수와 대표 예)를 알린다.

## 서식 표준 (build_doc.py가 적용 — 수정은 스크립트에서)

Google Docs의 HTML 가져오기에서 살아남는 속성만 쓴다(인라인 스타일, 표 셀 배경·테두리, 글꼴·크기·색·굵기, 문단 여백·줄 간격).
문단 배경·좌측 강조선·flex·클래스 CSS는 유실되므로 쓰지 않는다. 디자인 값은 스크립트 상단 '디자인 토큰'에 모여 있다.

- 글꼴 **Noto Sans KR**(Docs 기본 제공. 맑은 고딕은 Docs에 없어 Arial로 바뀐다). 본문 11pt, 왼쪽 정렬, 줄 간격 1.7, 문단 뒤 10pt.
- 색: 본문 `#202124`, 보조 `#5f6368`, 강조(제목·소제목·표 머리) 남색 `#1f4e8c`.
- 머리말: 작은 남색 머리글(아카이브·모드) → `<h1>` `[카테고리] 영상 제목` → 정보 표(영상·채널·게시일·길이·전사 출처) → 노란 '읽기 전에' 상자.
- Mode A: 목차 표(시각 링크 + 번호 + 소제목) → `01  소제목` 형식 소제목 + "▶ 시작–끝 영상에서 보기" 링크 →
  문단마다 앞에 회색 작은 타임스탬프 링크(1시간 미만 영상은 `mm:ss`) → 부록 '주요 교정 어휘' 표 → 바닥글(버전·아카이빙 날짜).
- Mode B: 번호 소제목, 핵심 명제는 하늘색 상자, 요약표 머리는 남색 바탕 흰 글자.
- 상자는 1칸 표로 구현한다. 이모지 등 BMP 밖 문자는 숫자 참조로 바꿔 Drive 변환에서 깨지지 않게 한다.
- 타임스탬프 링크는 `https://www.youtube.com/watch?v=<ID>&t=<초>s`. 썸네일·스틸컷 등 이미지는 넣지 않는다.
